## 1. 실제 명령 속도 경로 정리

- Planning의 `max_drive_speed_kmh` 선언·읽기·`min()` 제한과 해당 진단 토픽을 제거했다.
- `morai_speed_admission_enabled`, `morai_validated_speed_cap_kmh`, 검증 거리/지연값의
  시작 설정·정책 생성·실제 명령 제한과 `admitted_speed_cap_kmh` 진단을 제거했다.
- `stopping_speed_cap()`의 차량 명령 연결을 제거했다. 과거 보고서의 수학 유틸리티는
  남아 있으나 주행 노드에서 import/호출하지 않는다.
- 선택적 거리 검증 모델의 고정 속도 cap으로 실제 명령을 자르던 연결도 제거했다.
  센서/관측/정지거리 실패에 따른 정지 판단은 유지했다.
- NORMAL은 직선과 일반 커브를 통합한다. `cruise_speed_kmh=60`,
  `sharp_curve_speed_kmh=30`, S4 10이 현재 기본 프로파일이다.
- 일반 커브 25km/h 모드와 자동 횡가속도 기반 추천 속도 상한을 제거했다.
  급커브 선행 제동은 설정된 급커브 목표만 사용한다.
- 진입 기하 대기의 별도 3km/h 제한을 제거했다. 검증된 같은 차선 경로만
  설정된 S4 속도로 사용할 수 있으며 그 경로도 검증에 실패하면 정지한다.
- FSM·센서 신선도·무효 입력·session 만료·수동 정지·S4 충돌/기하/rollout 검사는 유지했다.

60/30은 절대 최고속도가 아니다. 70/40, 90/50 목표에 숨은 추가 상한이 없는지는
격리된 계산/노드 테스트로 확인했다. 해당 속도의 실제 MORAI 추종 성공을 뜻하지 않는다.
저속 Launch는 사용자가 명시적으로 선택하는 과거 5/3 시험용 프로파일로만 남긴다.

## 3. 새 배치 직접 조사와 차선 검증 개선

MORAI의 읽기 전용 Actor API에서 Ego와 장애물 2/3/4를 확인했다.
MGeo의 명시적 허가 필드는 없지만 원본 `local_data/kcity_hdmap`의
`B2_SURFACELINEMARK.shp/.dbf/.shx/.prj`가 있었다. 추가 지도 정보를 사용자에게
다시 요구하지 않고 기존 파서와 코드표를 재사용했다.

`HDMapBoundaries`는 기존 LaneNetwork의 상호 인접·동일 방향·연속 기하 검사를 유지한다.
MGeo와 원본 A2_LINK 중심선의 양방향 거리 5cm 이내 일치를 먼저 확인한다.
명시적 차선 변경 금지는 항상 우선한다. 허가 속성이 없는 경우에도 정규 차로의
공유 흰 단일 점선 일반 차선(212/503)이 확인되면 기존 기하 검사를 거쳐 후보를 만든다.
금지·미확인 경계에 대해서는 추측으로 허용하지 않는다.
중앙선·실선·안전지대 등과 실제 차체 swept polygon이 접촉하면 경로를 거부한다.
이 검사는 S4 rollout과 실제 자세의 차체 검사에도 연결된다.
점선 속성만으로 법적 허가나 지도 정확도 전체가 증명됐다고 주장하지 않는다.
