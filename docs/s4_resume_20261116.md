## 2. 해결한 문제

### 고정 기하와 최신 장애물 검사의 분리

- 정확한 두 sampled 자세와 차체 치수로 고정 swept polygon을 재사용한다.
  자세를 반올림하거나 다른 자세의 증명을 재사용하지 않는다.
- 지도 증명은 Network·경계·검증 도로 영역 객체, 차체, 설정, 관측 곡률 범위,
  추가 진입 추종 여유를 포함한 문맥으로 구분한다. 객체 참조를 유지해 ID 재사용도 방지한다.
- 고정 차체 기하와 지도 증명은 각각 최대 12,000개 LRU로 제한한다.
  지도는 로딩된 고정 객체를 사용하며 지도 재로딩 시 객체를 교체하는 계약이다.
- 매 호출마다 남은 경로와 **최신 보수적 장애물 memory 전체**를 검사한다.
  같은 꼭짓점의 새 관측에서도 장애물 검사를 생략하지 않는다.
- 현재 측정 차체 검사와 현재 자세·속도·조향으로 시작하는 PP rollout은 유지한다.
  rollout의 지도 검사는 고정 경로 캐시로 대체하지 않는다.
- EntrySearch·ReturnSearch의 snapshot에는 독립된 캐시를 사용한다.
  결과 채택 전 최신 입력 재검증과 3개 신선한 자세 interlock은 유지한다.

### 실제 도로 전체에서 Offset 탐색

- 관측 장애물 폭에서 탐색 시작값을 만들던 의존성을 제거했다.
- 검증된 convex cell 합집합의 정확한 횡단면 구간을 구하고, 구멍을 보존한 채
  각 구간을 검사한다. 횡단면은 탐색 범위일 뿐 통과 허가는 아니다.
- 최대 9개 분산 후보와 최대 4회의 전체 경로 성공/실패 사이 정밀 탐색을 사용한다.
  각 후보는 기존 차체·장애물·도로·곡률·PP 검증을 모두 통과해야 한다.
- 경계에 너무 붙은 명목 경로가 다음 측정 자세의 예측에서 거부되는 모델 회귀를 발견했다.
  도로 Offset 진입 후보에는 **허용 추종 오차만큼 추가 지도 여유**를 둔다.
  기본 추종 한계 0.30m에서 명목 진입은 0.60m, 주행 중 검증은 기존 0.30m다.
  장애물 차체 간격 0.25m, reference clearance 1.20m 등 기존 기준은 유지했다.
- 교차로 연결부나 지도 근거가 없는 공간을 메우지 않는다.

### HOLD의 먼 미래 경로로 인한 오정지

- 80m HOLD 꼬리가 먼 지도 cap이나 추종 불가능한 native 굴곡까지 포함해
  현재 안전한 구간에서도 정지시키는 원인을 실제 로그로 확인했다.
- 첫 미검증 sweep/굴곡 전에 안내 경로를 끝내고, 잘린 끝점의 자세도 다시 검증한다.
  구멍을 건너뛰거나 경로를 smoothing하지 않는다.
- 전체 Control/rollout 지원 길이를 확보하지 못하면 정지한다.
  가까운 지도 구멍·급격한 곡률·추가 장애물 거부는 음성 테스트로 확인했다.

### 센서 callback 지연과 시험 도구

- HOLD/신선도 상태가 바뀔 때마다 174개 후보 도형을 다시 만들던 RViz 경로를 분리했다.
  상태 텍스트는 매 주기 갱신하고, 같은 후보 도형은 0.5초마다 갱신한다.
  도형 수명 2초 및 후보 변경/삭제는 유지한다. 제어 경로에는 영향을 주지 않는다.
- 이전 세션의 시험 도구를 재사용해 `tools/s4_morai_generalized_trial.py`로 보존했다.
  원래 Actor와 충돌하지 않는 임시 배치, 단일 제어 발행자, 정지·센서·경로 준비를 검사한다.
- SIGINT가 ROS context를 먼저 닫아 cleanup이 중단되던 문제를 수정했다.
  초기 실패 시험은 별도 정지·수동 복원으로 회수했다. 이후에는 독립 신호 처리,
  복구 journal, 실행 중 JSONL 저장, 정지 후 배치·설정 복원 확인을 사용했다.
- Actor API는 임시 배치·복원·사후 검증에만 사용한다.
  실제 회피 planner에는 LiDAR 관측이 입력되며 Actor 정답 좌표를 주입하지 않는다.
